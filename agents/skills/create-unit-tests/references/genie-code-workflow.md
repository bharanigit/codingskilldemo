# Claude Code Workflow

Use this reference only when creating or updating pytest unit tests from Claude Code in Databricks. The common test structure, fixture rules, mocks, and assertions remain defined in `implementation-guide.md`.

## Preserve the Repository Test Contract

Generate ordinary pytest modules under `databricks/tests/unit/`. Do not generate Databricks test notebooks, `%run` cells, top-level assertion cells, or `dbutils`-based path setup. Do not add workspace paths to generated imports or `sys.path` statements. The PR pipeline resolves all imports from the checked-out repository.

## Detect the Workspace Context

Use available runtime evidence such as a `/Workspace` filesystem or Databricks runtime environment variables. Do not ask the user to identify the environment when it can be detected. If the environment remains ambiguous, preserve the local pytest format and do not perform workspace mutations.

## Read Source Notebooks

All entity definitions and transformation logic come from reading the source notebook directly. No compiled artifacts, no compiler script.

Search for the target notebook in this order:

1. The current Git folder at the path the user named.
2. `/Workspace/Shared/release/...` as a read-only reference when the repository copy is unavailable.

Never modify, copy, or write to `/Workspace/Shared/`. Always generate tests that import from ordinary Python paths so they run in local development and CI without workspace modifications.

## Freshness

The source notebook is always the authoritative reference for entity definitions, attribute types, and transformation logic. If the notebook has changed since any previously inspected reference, re-read it before generating or updating a test.

## Do Not Execute Pytest in Claude Code

After generating a test module and fixtures, defer execution:

```text
The unit test and synthetic fixtures were generated by reading the source
notebook directly. No compiled artifacts were required.

Pytest was not executed in Claude Code. Run the target test locally, or use
the PR unit-test pipeline, which runs pytest before deployment.
```

Do not create, replace, or modify `conftest.py`, `pytest.ini`, runtime stubs, test utilities, Spark master settings, or Spark-session configuration to make tests run on an active Databricks cluster. Do not generate an alternate Databricks-only test harness.

## Report Generation Honestly

State:

- Which source notebook was read
- Which entity definitions were copied into the test
- Which transformation expressions were extracted as the standalone function
- Which fixture CSV files were created and their paths
- Which behaviors are covered by each test function
- Any mocks applied and why
- Any remaining limitations or untested branches

Never claim test success based on reading source code or generating test files. Only claim test execution if pytest actually ran locally.
